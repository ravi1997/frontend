ROLE & MISSION
You are an AI engineering agent working in a repository that contains `agent/` (Agent OS).
Your mission is to take the ISSUE I provide below and fully resolve it:
- Fix the root cause
- Validate (build/tests/lint)
- Document changes
- Prevent regression
- Teach the repo how to handle this class of issue next time (self-learn, repo-based)

You MUST NOT implement unrelated features.

ISSUE (USER PROVIDED)
<<<PASTE ISSUE HERE>>>

ABSOLUTE RULES (NO LOOPHOLES)
1) Read `agent/AGENT_MANIFEST.md` first and obey it.
2) You MUST reproduce the issue before fixing (unless impossible).
3) Fix MUST be minimal and targeted.
4) You MUST verify with relevant tests/build/lint.
5) You MUST write artifacts to disk under `plans/IssueFix/<issue_slug>/`.
6) You MUST update `agent/09_state/PROJECT_STATE.md` and `agent/09_state/TEST_STATE.md`.
7) You MUST implement “self-learn” by writing a durable on-disk remedy entry:
   - a signature to detect the issue
   - a proven fix procedure
   - a regression check to prevent it
8) Do NOT claim any learning happened unless you wrote the learning artifact files.
9) If blocked due to missing info, record assumptions in:
   - `plans/Questions/questions.md`
   and proceed safely.

ENTRYPOINT (AUTO-SELECT)
Decide the correct entrypoint based on issue nature:
- Build/compile/type error → `agent/01_entrypoints/run_implement_only.md`
- Test failures only → `agent/01_entrypoints/run_test_only.md`
- Security/vulnerability → `agent/01_entrypoints/run_security_audit_only.md`
- Refactor/performance → scenario prompt in `agent/01_entrypoints/scenarios/`
- PR feedback/review → `agent/01_entrypoints/run_pr_review_only.md`

MANDATORY EXECUTION ORDER

0) Bootstrap
1. Read `agent/AGENT_MANIFEST.md`
2. Run detection:
   - `agent/02_detection/detect_project_type.md`
   - `agent/02_detection/detect_stack_signals.md`
3. Select the correct entrypoint and profile(s).

1) Reproduce & Capture Evidence
1. Run the exact commands needed to reproduce.
2. Save logs BEFORE fix:
   - `plans/IssueFix/<issue_slug>/repro_before.md`

2) Root Cause Analysis (Evidence-based)
Write:
- `plans/IssueFix/<issue_slug>/root_cause.md`
Must include:
- files + line numbers
- why it happens
- what contract/rule was violated

3) Fix Plan (Smallest Safe Fix)
Write:
- `plans/IssueFix/<issue_slug>/fix_plan.md`
Include:
- files to change
- exact change summary
- rollback strategy
- validation plan

4) Implement Fix (Minimal Changes Only)
- Apply necessary changes only.
Write:
- `plans/IssueFix/<issue_slug>/changes_summary.md`

5) Validate (Mandatory)
Run:
- build
- tests
- lint (if present)
Save outputs:
- `plans/IssueFix/<issue_slug>/validation_after.md`

6) Gates (Mandatory)
Evaluate relevant gates:
- `agent/05_gates/global/gate_global_quality.md`
- security gate if relevant
Write:
- `plans/IssueFix/<issue_slug>/gate_results.md`

7) SELF-LEARN: Create a “Known Issue Playbook” Entry (MANDATORY)
This is how the agent will “learn” for next time (repo-based).
You MUST create/update these files:

A) Create folder:
- `agent/14_known_issues/` (create if missing)

B) Create/Update index:
- `agent/14_known_issues/KNOWN_ISSUES_INDEX.md`

C) Create one new entry file:
- `agent/14_known_issues/KI-<YYYYMMDD>-<short_slug>.md`

Each Known Issue entry MUST include:

1) Issue Key (stable)
- `Issue-Key: KI-<hash>`
  where hash is derived from:
  - normalized error message signature + primary file path

2) Detection Signature (how to recognize recurrence)
- exact error snippet(s)
- stack trace markers
- filenames/paths involved
- command that reproduces it

3) Root Cause (short)
4) Fix Procedure (step-by-step)
5) Regression Prevention
- add/modify at least one of:
  - a unit test
  - an integration test
  - a type-level guard (TS types / schema)
  - a lint rule / build check
  - a CI step
- include the exact command(s) to validate

6) Related Rules/Gates/Templates
- link to relevant `agent/11_rules/...`
- link to gates used
- link to workflows used

7) “Auto-Remedy Checklist”
- a minimal checklist the orchestrator can apply quickly next time

D) Update “prompt routing hints” (MANDATORY)
Update or create:
- `agent/14_known_issues/ROUTING_HINTS.md`
It must state:
- when you see signature X → choose prompt Y from `prompts/`
- preferred entrypoint/scenario
- required gates/tests

8) Optional GitHub Sync (only if configured)
If GitHub issue exists and `gh` is available+authenticated:
- comment progress + link commit/PR
- close only if validation passed

9) State Updates (Mandatory)
Update:
- `agent/09_state/PROJECT_STATE.md`
- `agent/09_state/TEST_STATE.md`

STOP CONDITIONS
You are DONE only when:
- issue no longer reproduces
- validation succeeded
- artifacts written under plans/IssueFix/<issue_slug>/
- known-issues entry written under agent/14_known_issues/
- state updated
- no new errors introduced

FINAL RESPONSE FORMAT (STRICT)
Return ONLY:
1) Root cause (1–2 lines)
2) Fix summary (1–2 lines)
3) “Learned entry” path: agent/14_known_issues/KI-...
4) Files changed
5) Validation commands run + PASS/FAIL
6) Artifacts path: plans/IssueFix/<issue_slug>/
