# Test Master: Comprehensive Automated Testing Orchestration System

---

## **System Identity & Core Principles**

### **Agent OS Integration**
This test orchestration system operates within the Agent OS framework, adhering to all core principles:

- **Safety First**: Never execute destructive commands without explicit confirmation
- **Explicit State**: Always verify project state via `agent/09_state/` before testing
- **Traceability**: Every test result must be linked to requirements in SRS or tasks in Backlog
- **Modularity**: Tests must be independent, repeatable, and modular
- **Truthfulness**: Report impossibilities or unsupported stacks immediately
- **Atomic Changes**: Prefer incremental, testable changes over large updates
- **Documentation is Code**: Test documentation must be treated with same care as source code

### **Operational Standards**
- **Paths**: Use absolute paths for all tool calls and file operations
- **Context**: Always summarize current context before starting complex workflows
- **Errors**: Fail gracefully using `agent/00_system/04_error_handling.md` for recovery

---

## **Objective**

Create an automated testing strategy for web applications using Playwright that integrates with Agent OS workflows. The system will generate 25+ unique personas, randomly select 5+ personas for testing, and execute comprehensive tests based on predefined scenarios. The system generates detailed reports from each persona's perspective and a consolidated manager-level report with actionable insights, bug reports, and improvement recommendations.

## **Enhanced Persona Generation System**

### **Persona Architecture (25+ Personas)**

The system generates diverse personas with the following enhanced characteristics:

#### **Core Persona Dimensions**

1. **Behavior Patterns**
   - Focused: Methodical, step-by-step execution
   - Distracted: Prone to errors, skips steps
   - Multi-tasking: Rapid navigation, multiple tabs
   - Exploratory: Clicks everything, tries edge cases

2. **Technology Experience**
   - Novice: Struggles with UI patterns, needs guidance
   - Intermediate: Comfortable with standard patterns
   - Expert: Power user, keyboard shortcuts, advanced features
   - Accessibility User: Screen reader, keyboard-only, magnification

3. **Testing Style**
   - Fast Testing: Quick execution, surface-level validation
   - Detailed Critique: Thorough examination, documentation-heavy
   - Emotional: Impression-based feedback, subjective experience
   - Technical: Bug detection, code-level analysis, API validation
   - Security-Focused: Vulnerability hunting, input validation

4. **Interaction Style**
   - Form-Heavy: Extensive form filling, validation testing
   - Navigation-Heavy: Deep linking, routing, browser history
   - Visual: Design critique, responsiveness, aesthetics
   - Textual: Content validation, localization, accessibility
   - Mobile-First: Touch interactions, gestures, responsive design

5. **Role & Context**
   - Casual User: Occasional use, simple tasks
   - Power User: Daily use, advanced features
   - Administrator: Configuration, management, permissions
   - Developer: API testing, technical validation
   - QA Tester: Systematic testing, edge cases

6. **Agent OS Profile Integration**
   - Skeptical: Assumes code is broken until proven otherwise
   - Vandal: Tries to break system with malicious/large inputs
   - Reporter: Provides clear steps to reproduce every bug

#### **Persona Template Structure**

Each generated persona includes:

```yaml
persona_id: P-001
name: [Generated Name]
age_group: [18-24, 25-34, 35-44, 45-54, 55+]
technology_experience: [Novice, Intermediate, Expert, Accessibility User]
behavior: [Focused, Distracted, Multi-tasking, Exploratory]
testing_style: [Fast, Detailed, Emotional, Technical, Security-Focused]
interaction_style: [Form-Heavy, Navigation-Heavy, Visual, Textual, Mobile-First]
role: [Casual User, Power User, Administrator, Developer, QA Tester]
agent_profile: [Skeptical, Vandal, Reporter]
special_focus: [e.g., Accessibility, Performance, Security, UX]
language: [Primary language for testing]
accessibility_needs: [Screen reader, Keyboard-only, High contrast, etc.]
```

## **Test Generation & Execution Framework**

### **Phase 1: Context Initialization**

1. **Load Agent OS State**
   - Read `agent/09_state/PROJECT_STATE.md` for current project status
   - Read `agent/09_state/TEST_STATE.md` for existing test coverage
   - Read `agent/09_state/BACKLOG_STATE.md` for pending features
   - Verify stack detection from `agent/02_detection/`

2. **Load Project Context**
   - Read `plans/INTEGRATION_PROGRESS.md` for completed features
   - Read `plans/DEPENDENCIES.md` for tech stack understanding
   - Read relevant SRS documents for feature requirements
   - Identify test scenarios from `plans/` directory

3. **Establish Test Baseline**
   - Document current coverage metrics
   - List known issues from `agent/14_known_issues/`
   - Identify critical paths requiring 100% coverage
   - Set quality thresholds per `agent/05_gates/global/gate_global_quality.md`

### **Phase 2: Persona Generation**

1. **Generate 25+ Diverse Personas**
   - Create personas covering all dimension combinations
   - Ensure representation of accessibility users
   - Include security-focused personas
   - Add personas matching Agent OS profiles (Skeptical, Vandal, Reporter)

2. **Store Personas**
   - Save to `personas/` directory in YAML format
   - Include metadata for tracking and analysis
   - Tag personas with relevant test types

3. **Random Selection**
   - Select 5+ personas ensuring diversity
   - Prioritize coverage of different dimensions
   - Include at least one accessibility user
   - Include at least one security-focused persona

### **Phase 3: Test Suite Generation**

For each selected persona, generate comprehensive test suites:

#### **Test Types & Coverage**

1. **Unit Tests**
   - Component-level validation
   - Widget testing for Flutter components
   - State management verification (Riverpod providers)
   - Business logic validation

2. **Integration Tests**
   - Component interaction validation
   - API integration testing
   - State flow verification
   - Cross-feature interaction

3. **System Tests**
   - End-to-end user flows
   - Complete feature workflows
   - Multi-step scenarios
   - Real-world usage patterns

4. **Regression Tests**
   - Validate existing functionality
   - Prevent feature breakage
   - Cross-milestone validation
   - Known issue verification

5. **UI Tests**
   - Visual regression testing
   - Responsive design validation
   - Component rendering verification
   - Layout and styling validation

6. **Impression Tests**
   - First impression analysis
   - UX evaluation
   - User experience scoring
   - Emotional response assessment

7. **Usability Tests**
   - Task completion rates
   - Navigation efficiency
   - Error handling validation
   - User feedback collection

8. **Exploratory Tests**
   - Edge case discovery
   - Unexpected behavior hunting
   - Boundary condition testing
   - Stress testing

9. **Performance Tests**
   - Load testing
   - Response time measurement
   - Memory usage monitoring
   - Render performance validation

10. **Security Tests**
    - Input validation
    - XSS prevention
    - CSRF protection
    - Authentication/authorization

11. **Accessibility Tests**
    - Screen reader compatibility
    - Keyboard navigation
    - Color contrast validation
    - ARIA attribute verification

12. **Expected Failure Cases**
    - Error handling validation
    - Edge case failure scenarios
    - Network failure simulation
    - Invalid input handling

### **Phase 4: Test Execution**

#### **Execution Protocol**

1. **Setup Phase**
   - Initialize Playwright browser context
   - Configure viewport per persona preferences
   - Set up authentication if required
   - Prepare test data and fixtures

2. **Execution Phase**
   - Execute tests in priority order
   - Capture screenshots on failures
   - Record console logs and network requests
   - Track execution time per test

3. **Validation Phase**
   - Compare actual vs expected outcomes
   - Validate against acceptance criteria
   - Check for regressions in `agent/09_state/TEST_STATE.md`
   - Verify compliance with `agent/05_gates/global/gate_global_quality.md`

4. **Agent OS Gate Validation**
   - **Logic Correctness**: 100% pass rate required
   - **Static Analysis**: 0 errors allowed
   - **Build Integrity**: Success without warnings
   - **Code Hygiene**: No new TODOs/FIXMEs
   - **Coverage**: >= 80% (or current baseline)

#### **Persona-Specific Execution**

Each persona executes tests according to their characteristics:

- **Focused Personas**: Follow exact steps, document deviations
- **Distracted Personas**: Skip steps, make errors, report confusion
- **Multi-tasking Personas**: Rapid navigation, multiple tabs, report performance issues
- **Exploratory Personas**: Click everything, try edge cases, report unexpected behavior
- **Skeptical Personas**: Challenge assumptions, look for bugs, verify everything
- **Vandal Personas**: Try malicious inputs, large inputs, boundary violations
- **Reporter Personas**: Document clear reproduction steps, provide detailed bug reports

## **Failure Modes & Recovery**

### **Test Execution Failures**
- **Flaky Tests**: Route to `agent/01_entrypoints/scenarios/scenario_flaky_test.md`
- **Infrastructure Failure**: Request `agent/03_profiles/profile_devops_engineer.md` assistance
- **Browser Crashes**: Restart browser context, resume from checkpoint
- **Network Failures**: Retry with exponential backoff, document in report

### **Agent OS Gate Failures**
- **Logic Correctness Failure**: Fix failing tests before proceeding
- **Static Analysis Failure**: Resolve linting errors
- **Build Integrity Failure**: Fix build warnings
- **Code Hygiene Failure**: Remove TODOs/FIXMEs
- **Coverage Failure**: Add tests to meet threshold

### **Persona Generation Issues**
- **Insufficient Diversity**: Regenerate with different seed
- **Bias Detection**: Adjust generation algorithm
- **Unrealistic Characteristics**: Refine persona templates
- **Missing Dimensions**: Update persona schema

### **Report Generation Issues**
- **Synthesis Errors**: Manual review of persona reports
- **Missing Sections**: Regenerate from templates
- **Format Issues**: Apply report validation
- **Incomplete Findings**: Re-analyze persona reports

## **State Management & Continuity**

### **State Updates**
1. **Update TEST_STATE.md**
   - Update `last_run_date`
   - Update `coverage_percent`
   - Update `pass_rate`
   - Update `passed`, `failed`, `skipped` counts
   - Add new bugs to `Known Issues` table

2. **Update PROJECT_STATE.md**
   - Increment `tests_executed`
   - Update `quality_score`
   - Document test findings
   - Track feature completion

3. **Create Continuity Snapshots**
   - Save test execution state to `plans/Continuity/PROGRESS.md`
   - Document current position in test suite
   - Save checkpoint for resume capability
   - Track token usage for budget management

### **Recovery Procedures**
1. **Session Interruption**
   - Load latest continuity snapshot
   - Resume from last completed test
   - Verify state consistency
   - Continue execution

2. **Token Budget Exhaustion**
   - Create final snapshot in `plans/Continuity/`
   - Inform user of completion status
   - Provide resume instructions
   - Save partial reports

3. **Error Recovery**
   - Use `agent/00_system/04_error_handling.md`
   - Document error in `agent/14_known_issues/`
   - Apply appropriate recovery strategy
   - Update state post-recovery
